# Relay setup scope

Read README.md and inspect setup.py before acting. Work only in the user's selected copy and Cloudflare account. Ask the user to complete Wrangler sign-in; never request their account password. Confirm the explicit account ID, unique worker name and destination Tonk space DID before the first deployment. Run local tests first. Use setup.py's configure-only invocation to prepare an inspectable destination, then its explicit --deploy mode when authorized. Never deploy to the pre-existing VPS or alter unrelated workers.

Keep query capabilities private: no stdout, argv, public template, issue, telemetry or raw tail logs. Read .relay-private/capability.txt in-process. Do not expose .dev.vars or private state in the template bundle. Use the carried Free-compatible configuration without changing the account plan. Inspect billing/plan information only when existing authorization permits it. If billing-read permission is unavailable, report the account plan as unverified and continue the otherwise authorized setup; do not claim verified Free entitlement, request broader OAuth access solely for billing, or treat the missing permission as requiring an upgrade. Stop if deployment actually requires an upgrade, payment or acceptance of charges, and obtain the owner's authorization. Use workers.dev; custom DNS is unnecessary.

After deployment, run the authenticated two-WebSocket smoke test to verify signalling, origin-null support and rejected bad tokens/origins. Once it passes, snapshot the intended destination's nightsky-relay fact privately, then configure only that fact with the new private capability URL. In the actual Tonk space, verify two-browser playback, seek, pause, cursors and leave/rejoin, plus two newly created song rooms without server allowlist edits. If acceptance fails, restore only the backed-up relay fact after checking that no newer user edit would be overwritten. Preserve existing songs, comments, shelf, workspace selection and components. Keep the old VPS operating unless the user explicitly authorizes retirement. Report local tests separately from real deployment/browser results.
